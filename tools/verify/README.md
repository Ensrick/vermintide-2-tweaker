# verify / generate_playtest

Improvement #3a from the 2026-07 standards review. Turns the pile of open issues that
are **waiting on a human in-game verify** into ONE ordered playtest walk, so the tester
runs a single session top-to-bottom instead of opening ~100 issues and wandering the
game per-issue.

`generate_playtest.ps1` reads the open issues carrying a verify-state lifecycle label,
pulls each issue's shipped TEST METHOD out of its comments, classifies the check by where
in the game it happens, and writes two regenerated docs.

## Run

```powershell
pwsh tools/verify/generate_playtest.ps1              # pull live issues, write both docs
pwsh tools/verify/generate_playtest.ps1 -SelfTest    # offline unit test of the heuristics (no network, no writes)
pwsh tools/verify/generate_playtest.ps1 -OutDir C:\tmp\pt   # write the docs elsewhere
pwsh tools/verify/generate_playtest.ps1 -Limit 200   # cap issues fetched per label
```

Requires the `gh` CLI authenticated for github.com as `Ensrick`, and PowerShell 7+.
Read-only against GitHub; writes only the two docs; **does not commit**.

## Inputs

Open issues labeled any of:

- `verify-fix` - fix shipped, confirm in-game (solo).
- `verify-fix-coop` - fix shipped, needs 2+ people to confirm.
- `diagnostics-armed` - a probe is armed; trigger it and read the log.

Issues are de-duplicated by number (an issue under two labels appears once).

## Outputs (overwrite each run - regenerate, never hand-edit)

- `docs/PLAYTEST_SCRIPT.md` - the full solo + co-op walk for the author / primary tester.
  Task-list checkboxes, one per issue, each with the extracted one-line check and the
  expected evidence (log marker + pass condition). Footer carries the rough per-section
  time estimate and the MISSING-METHOD list.
- `docs/PLAYTEST_COOP.md` - a compact co-op-only variant in plain language for a second
  tester (RainReligion) with no repo context: jargon stripped, no em dashes, generic
  PASS lines where the real evidence is too technical to plain-language.

Both docs open with a `GENERATED by ...` banner. If you need to change them, change the
tool (keyword lists / heuristics) and rerun - hand edits are lost on the next run.

## How a check is placed (walk order)

Classification is best-effort keyword matching over the method text + title. Sections are
ordered so the tester loads the game as few times as possible and batches mission-only
checks into one run each:

| Section | Catches (keywords) |
|---|---|
| `KEEP-MENU` | keep menus: hero view, inventory, talent/tooltip, Athanor/forge, loadout, options, cosmetic/illusion/portrait, dropdown/widget. No mission load. |
| `KEEP-WORLD` | wield/draw, bots, bot-husk visuals inside the keep. |
| `MISSION-ADVENTURE` | mission / adventure / level / horde / `dlc_` - batched into one Adventure run. |
| `MISSION-CW` | chaos wastes, citadel, shrine, boon, curse, deus, pilgrim, expedition - one CW run. |
| `SCORE-END` | scoreboard, score sync, round end, results/victory/defeat screen. |
| `SHUTDOWN` | boot flood, warning flood, on/at boot, quit to desktop, restart, read the log. |
| `COOP-2P` / `COOP-3P` | the `verify-fix-coop` label, or method text naming 2+/3+ players, both peers, host+client, cold-join, remote husk. 3 players / host-bot + clients -> 3P, else 2P. |

When a check lands in the wrong section, the fix is to make the issue's method comment
clearer (name the location) or to adjust the keyword lists at the top of the script -
then regenerate. Do not hand-edit the doc.

## How the TEST METHOD is extracted

Per issue, every comment is scored and the highest-scoring one wins (ties break to the
most recent):

- `+` for `Test method`, an uppercase `TEST`, `test with/as/in/(`, `to verify`,
  `pass =`, `expected:`, numbered steps, and a `[mod:marker]` log tag.
- `-` for label/xref bookkeeping (`verify-fix was set...`, `cross-ref`, `re-applying`)
  and very short comments.

If nothing clears the threshold the issue is flagged **MISSING-METHOD** and falls back to
a link to the issue. MISSING-METHOD is a doctrine violation (every ship owes a runnable
test comment - see `PROJECT_STANDARDS.md` §11 and `feedback_status_labels_on_ship`); the
footer lists every offender so the gap gets a comment posted.

## Time estimate model

Rough by design. Per section: `overhead (paid once, e.g. one mission load) + count *
per-check observe time`. Checks batch into the section's run, so per-check stays small.
Tune `Over` / `Per` in the `$sections` / `$coopSections` tables.

## Self-test

`-SelfTest` runs offline unit tests of the method-selection, check-line, evidence,
classification, and plain-language helpers. It must print `SELF-TEST PASS` (exit 0) before
you trust a change to the heuristics. Add a case there when you add or change a rule.
