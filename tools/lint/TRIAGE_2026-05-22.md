## False positives in the lint script

These need scope/pattern fixes in `regression-lint.ps1`:

### forward-ref (7 false positives)

- weapon_tweaker.lua:794/820/856 — references `has` which is a **boolean local** inside each chat-command callback (`local ok_h, has = pcall(...)`), not a call to the nested `local function has(evt)` at L3211 that lives inside a *different* function's body. Lint is matching `has` as identifier without distinguishing variable-use (`if has then`, `tostring(has)`) from function-call (`has(...)`).

- _material_hijack_embedded.lua:44/45/46 — `replace_textures = function() end` etc. are *table-constructor inline function definitions*, not calls to the later `local function replace_textures(...)`. Lint isn't recognizing `KEY = function() end` as a definition.

- cosmetics_tweaker.lua:661 — `mod.on_game_state_changed = function() ... if mod._try_install_flow_glow_hook then mod._try_install_flow_glow_hook() end ... end`. `mod._try_install_flow_glow_hook` is a *table-field access* on the mod object, guarded by nil-check, not a local-function call. Lint is matching the identifier `_try_install_flow_glow_hook` regardless of `.`/`:` prefix.

**Recommended lint fix**: forward-ref check should
1. Only fire on `<name>(` (open paren) call form
2. Exclude usage where the identifier is preceded by `.` or `:`
3. Track scope at the function-body level — a nested `local function name` inside function A is invisible to function B's body
4. Recognize `<key> = function(...)` table entries as definitions (not call sites)

### strict-table-lookup BuffTemplates (17 false positives)

career_tweaker_balance.lua + career_tweaker_big_rebalance.lua: 17 sites flagged for `BuffTemplates[name]` outside rawget. **Vanilla VT2 BuffTemplates has no metatable** (verified against `C:/Users/danjo/source/repos/Vermintide-2-Source-Code/scripts/.../buff_templates.lua` — no setmetatable / __index). Only `NetworkLookup.buff_templates` (the network-id lookup) is strict, not `_G.BuffTemplates` (the data table).

**Recommended lint fix**: strict-table-lookup check should fire ONLY on `NetworkLookup.<anything>[key]`, not on `BuffTemplates[key]`. Remove BuffTemplates from the strict list.
