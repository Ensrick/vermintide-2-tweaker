Concrete primitives the harness needs, all present in the engine and cheap:
1. Run each mod's regression command and parse the summary. This alone re-tests the 84 named checks the cards rely on, and repeats the only experiment (2026-09-21) that has ever found real regressions here.
2. Spawn capture: record the unit path passed to the world spawner for hands, ammo, projectiles and previews. Decides #237, #279, #419, #1320 and the solo half of the husk cluster.
3. Retained-pose readback at +1, +30, +300 frames. Decides the transform cluster's machine half.
4. Backend item enumeration and loadout readback. Decides #592, #822, #628, #226, #273.
5. Career-action invariant sweep (F6). Decides #661 for every weapon, not three.
6. Animation probe. `Unit.has_animation_event` proves vocabulary only; the project already knows it can report state-machine stubs (`weapon_tweaker/.../_wt_anim_remap.lua:764-766`, `_wt_reload_3p.lua:99`, `character_weapon_variants/.../cwv_dev_anim_picker.lua:18-19`). The engine also exposes `Unit.animation_get_state` (`Vermintide-2-Source-Code/scripts/unit_extensions/default_player_unit/player_unit_locomotion_extension.lua:167`) and `Unit.animation_layer_info` (`scripts/flow/flow_callbacks.lua:328-329`); no mod uses either. Comparing state before and after a dispatched event would turn "nothing plays" from a visual report into an assertion [unverified at runtime]. Only cells that fail it need a person. That is the practical route through #948's 2,300 untested cells.
