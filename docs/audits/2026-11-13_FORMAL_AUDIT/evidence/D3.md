## Cross-cutting findings (read these first)

**F1 (S1). The Chaos Wastes stable tree is not "an older snapshot": it is a second, separately written implementation, and most live-test cards point at it.**
The dev entry file is 1,597 lines across 94 modules; the official entry file is 13,294 lines plus `_ct_official_*` leaf modules (`chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/_ct_official_chest_cap.lua`, `_ct_official_boon_repairs.lua`, `_ct_official_verify_runtime.lua`, `_ct_diag_official_apply_evidence.lua`, and others). The official changelog calls 0.7.354-beta a "selective official functional promotion ... not a wholesale Dev clone" (`chaos_wastes_tweaker/CHANGELOG.md:3-5`). The two trees register different check and command names for the same issue:

**F2 (S1). `/ct_regression_test` and its siblings mostly prove "the code loaded", not "the feature works".**
Heuristic classification of every `rt_register` body (`scripts/D3_rt_checks.py`; approximate, by what the body reads):

| Tree | Checks | Reads live engine state | Marker string only | Function presence only | Other |
|---|---|---|---|---|---|
| ct_dev | 115 | 25 | 42 | 22 | 26 |
| ct official | 81 | 17 | 17 | 14 | 33 |
| enemy_tweaker | 54 | 16 | 1 | 21 | 16 |
| event_tweaker | 20 | 7 | 1 | 4 | 8 |

Examples: #102's check compares a constant string (`_ct_regression.lua:749-756`); #322's check compares a marker (`_ct_boon_runtime_owner.lua:320-328`), which the owner's own 2026-08-04 log review called "a load-time marker check only". Several official checks are written to return SKIP without live state (`qa/lua/tests/test_ct_official_evidence_integration.lua:103` asserts `ct_meta_ammo_current_floor_256().status=="SKIP"`).
Worked example of the gap: the #471 hook installs only inside `if rawget(_G, "TerrorEventMixer") and TerrorEventMixer.init_functions ... then` with no else branch (`_ct_combat_hooks.lua:390-529`), while its markers are assigned unconditionally (`:362,386`) and all three related regression checks only compare marker strings (`_ct_regression.lua:673-678`, `:688-692`, `:700-707`). Static evidence suggests that if `TerrorEventMixer` were nil at mod load the feature would be absent and the suite would still pass. Runtime observation that would settle it: read VMF's hook registry for `spawn_around_origin_unit` in the keep.
An R harness must therefore bring its own assertions on engine state; the existing suites are useful only as a "nothing was stripped" gate.

**F3 (S0 process). A verify-fix card can be pinned for a feature that the mod's own changelog says cannot run.**
#451 is `verify-fix` with a card expecting `/et_spawn_chosen` to spawn a Chaos Chosen. `enemy_tweaker/CHANGELOG.md:3-12` (0.7.65-dev) records that "in 12 of 12 tester logs on 0.7.64-dev the transactional custom-breed registrar refused the Skaven Warlord (and the Chosen) at mod load with `damage_source_cap_unavailable`". Source agrees: registration runs at mod load (`_et_boss_ideas.lua:211`), the capacity reader needs `NetworkConstants` or `Network.type_info` (`_et_custom_breed_registrar.lua:509-523`), and the engine creates `NetworkConstants` only in `scripts/network_lookup/network_constants.lua:3`, dofiled from `state_loading_restart_network.lua:161` and `game_network_manager.lua:59`, after mods boot. The refusal was recorded on #324 on 2026-10-17; #451's card (2026-09-14, version string since auto-advanced) was not withdrawn. The card-validity guard checks card format and build identity, not whether the feature can execute. A human following that card would waste a session.

**F4 (S1). Closed "source-only, behaviour-preserving" work regressed runtime behaviour while every offline gate passed.**
Closed #1413 (registrar extraction, 2026-08-25) reports "3,172 Lua tests; focused registrar/network/adversarial matrix 52/52" and "behavior-preserving". The same changelog entry as F3 notes that 0.7.56-dev, before the registrar, still registered the breeds. The offline fixtures modelled a runtime (capacity readable at load) that does not exist in the game. This is the clearest evidence in the bucket that unit tests with hand-built fakes do not substitute for one boot of the real game.

**F5 (S2). Issue bodies, labels and cards drift apart; card dates do not identify builds.**
- Bodies of #107, #259, #289, #323, #342, #358, #917, #941 still say "Mark `not-started`" or "remains `not-started`" while the label is `verify-fix` and the fix is on master.
- #465 carries `blocked` + `not-started` although its change was published 2026-10-25; #1191 is `diagnostics-armed` although its fix shipped 2026-08-09; #253 is `diagnostics-armed` but its card tests shipped behaviour.
- Cards are edited in place to advance version strings: the #919 card dated 2026-08-20 names `v0.7.354-dev`, a build that shipped 2026-11-06 (`chaos_wastes_tweaker_dev/CHANGELOG.md:3`). The date on a card is not evidence of which build it was written against.

So 45 of 60 (75%) need no live player at any point, 3 need eyes, 7 need a second machine. By harness tier, R1 and R2 alone (boot, keep commands, one mission load, state readback, no scripted combat) reach 19 issues; the remaining 24 R issues need scripted in-mission actions.

Harness capabilities these issues require, in order of payoff:
1. Boot to keep with a named mod set, run a chat command, collect the console log (closes #1497, #1123, #1149, #802 and gives the #324 probe data).
2. Set mod options programmatically and enter one mission through `/ct_load_mission` (`_ct_dev_mission.lua:212`, present in both trees). This is why #505 should be verified first.

## 7. The ten issues that matter most

1. **#1497 (Rain, boot soft-lock).** Cause: the hot-join parity fence added for #451 treated every peer id as remote, held the listen server's own peer in `WaitingForEnterGame`, kicked it, then returned false forever from the sync hook. Fix is on master and Rain's log shows the keep loading. It stays open only because a named check failed for an unrelated reason (parity absent because registration was refused) and was never re-run. A boot-to-keep smoke test (local peer in game within 120 s, no script error, no `[MOD]...[ERROR]`, no `hot-join sync HELD|KICKED` for the local peer) closes it and would have caught the whole class before release: any hook on the boot, loading or peer-state path that blocks entry, and any missing bundled resource such as the #595 `_lib_appearance_fade.lua` case found in the same log.
2. **#324 (custom breeds do not register).** Root of the et-custom-breed cluster; blocks #451 and #452 and is a live regression from closed #1413. One run in the keep captures the probe rows that decide the fix.
3. **#451.** The clearest process failure in the bucket (F3): in the human test queue while unable to run.
4. **#919 (0-critical, profiles restore the wrong settings).** Affects every CT option a tester sets through Mod Tweaker profiles, so it can silently invalidate other verification. A static audit named a cause on 2026-08-03; no fix followed; the issue waits for a log that a script can produce. The snapshot still takes its members from the tab's display node list (`gui_tweaker_dev/.../_mod_tweaker_view.lua:773`, `_mod_tweaker_view_pending.lua:77-97`).
5. **#505 (Single Mission Loader).** Not severe by itself; it is the entry point the harness needs for 14 R2 issues and most R3 ones. Verify first, as a loop over the whole mission catalog.
6. **#426 (0-critical, public stream).** Crash for peers without the mod, shipped to public subscribers. Solo and unit coverage can go far, but the decisive leg needs a second client. Bundle #1191 and closed #406 into that one session.
7. **#430 and #413 (0-critical, Event Tweaker).** Same shape as #426 for curses and the Shadow mutator. #430's per-curse behaviour in Adventure was never verified even solo; that loop is automatable now.
8. **#1146, #458, #467 (start shrine and prices).** A regression that made the shop unusable, plus two features on the same code. One run-start scenario closes all three; the engine sentinel behind #1146 is confirmed.
9. **#470 (0-critical crash, vanilla data hole).** Small fix, confirmed engine cause, reachable through the mod's own progressive difficulty (#460). One mission load at Cataclysm 3 closes it; the static sweep prevents siblings.
10. **#460 and #349 (Rain).** The playtester's own requests. #460 needs the multi-map run (R4); #349 is a 30-second census on one map that has waited since July for someone to load it.

Also worth a line: **#1123** (installing Event Tweaker changed Chaos Wastes damage for everyone) is closable today from a keep readback, and **#322** is closable on static evidence.
