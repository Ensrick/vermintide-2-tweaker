**Assessment.** Accreted patches under a recent, disciplined-looking decomposition. The July audit recorded a 10,465-line entry; issue 1159 split it into about 100 files with injected dependencies and "owner" modules, and the pure policy modules are genuinely testable. But the split moved text, not responsibility: the same decisions are still made at 10+ hook entry points that infer context from ambient flags, the stores above are still independent, and modules still talk through 190 fields on the shared `mod` table. Comments carry the design history (43% of the entry is comment, every block cites the version that broke it), which shows how each rule was paid for and also that the structure is the sum of incident fixes. The project's own census agrees: 871 of 1,088 declared surface x edge pairs for this mod are "unsupported" (`docs/generated/APPEARANCE_CENSUS_GAPS.generated.md:28`).

### 2.3 character_dialogue

Entry `character_dialogue.lua` (682 lines) + `_cd_policy`, `_cd_browser`, `_cd_preview_policy`, `_cd_preview_residency`, `_cd_isolation_setting`. 2 hooks: `DialogueQueries.get_filtered_dialogue_event_index` (:388) and `TagQueryDatabase.iterate_query` (:399). No RPC. Persistence: `line_overrides` (sparse table keyed by Wwise event) and `auto_isolation`. 6 commands. Exposes `mod.character_dialogue_api` (version 6) consumed only by `gut_dev` (`character_dialogue.lua:368`); stable `gut` is deliberately not used.

How dialogue is injected: it is not. The mod (a) filters which line of an existing vanilla dialogue group the host selects, (b) suppresses a group whose lines are all disabled by clearing `query.result`, and (c) previews a line locally by `WwiseWorld.trigger_event` on the level Wwise world, loading `resource_packages/dlcs/morris_ingame` on demand for Chaos Wastes banks.

What commit `5aae53ae` (issue 881) changed (`git show --stat`): 31 lines in the entry. `package_status` now normalises `PackageManager.is_loading(package, reference)`, which returns a reference count rather than `true` (`foundation/scripts/managers/package/package_manager.lua:282-283`), one pending package owner is preserved, and the release log is bounded to 32 attempts and wrapped in `pcall`. 297 test lines were added. It did not touch line selection.

**Assessment.** Coherent, small, well factored into pure policies. It has one real logic defect in the selection path (A3-F01) that its tests cannot see because they stub the vanilla function.

### A3-F01 | S1 | correctness | Dialogue line overrides always select line 1 on a fresh dialogue group

Evidence. The hook builds its index source as `DialogueQueries.get_dialogue_event_index(dialogue, true)` (`character_dialogue/scripts/mods/character_dialogue/character_dialogue.lua:390`) and ends with `return index or 1` (:396). In vanilla, `wrap_around = true` skips `build_randomized_indexes` and only resets the counter (`Vermintide-2-Source-Code/scripts/entity_system/systems/dialogues/dialogue_queries.lua:85-107`). Every generated dialogue starts with `randomize_indexes_n = 0, randomize_indexes = {}` (for example `Vermintide-2-Source-Code/dialogues/generated/bright_wizard_bell.lua:133, 147`) and the file function is re-run per `DialogueSystem` (`.../dialogues/tag_query_loader.lua:64-78`), so a group that has an override from session start is never shuffled: each index is nil. `_cd_policy.lua` `choose_index` then reads `overrides[nil]`, the vanilla filter accepts a nil index, and the hook returns 1.

EMPIRICAL (offline): `scripts/A3_cd_fresh_group.lua` loads the real vanilla `dialogue_queries.lua` and the real `_cd_policy.lua`. Over 200 fresh 3-line groups each: "line a disabled" -> index 1 (the disabled line) 200/200; "line c force-enabled" -> 1, 200/200; "a and b disabled" -> 1, 200/200. On a group that vanilla shuffled once first, the same policy returns 2 and 3 evenly, so the policy is right and the index source is wrong.

Impact. For any group with 2 or more lines, disabling line 1 does nothing, disabling other lines pins the group to line 1, and force-enable never selects the chosen line.
