# ct scope-bug audit — 2026-05-23

After fixing `DORMANT_BOON_RARITY` (v0.7.99-dev), audited ct lua files for the same
late-local-shadows-global pattern (a top-level `local NAME` declared at line L while
code lexically above line L references the bare name `NAME` from inside a closure /
hook / event handler that runs at load time or later — the bare name resolves to
`_G.NAME` at compile time, never reaches the local declared further down).

Files audited:
- `chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/chaos_wastes_tweaker.lua` (7504 lines)
- `chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/chaos_wastes_tweaker_data.lua` (663 lines)
- `chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/_adventure_pool.lua` (808 lines)
- `chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/chaos_wastes_tweaker_mutex.lua` (115 lines)
- `chaos_wastes_tweaker/scripts/mods/chaos_wastes_tweaker/chaos_wastes_tweaker_localization.lua` (1115 lines)

Method: enumerated every top-level `local NAME` declaration (88 in the main file,
17 across the four sibling files), then for each declaration grepped for every
earlier bare-token reference to `NAME` and inspected the context.

## Findings

| File | Late local (line) | Earlier reference (line) | Risk | Suggested fix |
|------|-------------------|--------------------------|------|---------------|
| `chaos_wastes_tweaker.lua` | `local reckless_swings_originals = nil` (3822) | line 2100 — inside `mod:hook(_G, "Localize", function(func, key, ...) ... if key == "description_deus_reckless_swings" and reckless_swings_originals then return RECKLESS_SWINGS_DESC_OVERRIDE end ... end)` (closure registered at file-load) | **RISKY** | Promote to a global with a forward-declared empty value at the top of the file, mirroring the v0.7.99-dev `DORMANT_BOON_RARITY` fix. Either: (a) `_G.reckless_swings_originals = _G.reckless_swings_originals or false` near line 56 plus rewrite `local reckless_swings_originals = nil` at L3822 to drop the `local` keyword; OR (b) add `local reckless_swings_originals` (forward-declaration only) near line 322 — the existing "fwd-decl sync_*" group — so the Localize closure at L2100 captures the local upvalue slot, then the body at L3822 just removes the `= nil` initializer and becomes the assignment. Option (b) is the smaller, more conventional change and matches the pattern already used for `sync_reckless_swings`, `sync_bomb_cooldown`, `effective_setting`, `is_curse_disabled`, `_broadcast_local_manifest`, `sync_host_dependent_state`. |

Severity assessment: the bug is **silent — no crash, just a dead override path**.
The Localize hook returns `RECKLESS_SWINGS_DESC_OVERRIDE` only when
`reckless_swings_originals` is truthy. Because the bare token resolves to
`_G.reckless_swings_originals` (always nil — no code anywhere assigns to that
global; every assignment in `apply_reckless_swings_tweak`, `revert_reckless_swings_tweak`
writes to the local declared at L3822), the override branch never fires. The
tweaked Khaine's Fury description ("While above 25%% Health, gain 25%% Power but
take 1 damage on each melee hit.") is therefore never shown to the player; vanilla
description ("above 50%, take 3 damage") shows in tooltip even while the actual
gameplay numbers ARE patched (the apply path mutates `BuffTemplates` and
`description_values` directly — those don't go through this Localize hook).

Cosmetic only; no crash potential. Same shape as the DORMANT_BOON_RARITY bug but
without the dereference (the check is `and reckless_swings_originals then`, not
`reckless_swings_originals[name]` — so nil short-circuits safely).

## Recommendation

Fix the `reckless_swings_originals` scope bug at the next ct version bump. The
cleanest fix is a one-line addition near L322 (already the forward-declaration
block) — `local reckless_swings_originals` — followed by removing the `local`
keyword from the existing declaration at L3822 so it becomes a plain assignment.
This is a cosmetic fix (the tweaked tooltip will start showing the correct text);
not a ship blocker — the gameplay numbers ARE patched correctly. Low-effort
follow-up; can be batched with the next planned ct change rather than dispatched
as its own agent.
